# Источники данных

Оглавление: 1. Готовые скрипты канала · 2. Analytics API · 3. Показы и CTR (Reporting API + Studio) · 4. Data API · 5. Собственное хранилище · 6. Внешние источники · 7. Ограничения

## 1. Готовые скрипты канала

В репозитории `analiz_gide` уже есть рабочие скрипты для сбора данных. **Используй их в первую очередь**, а не пиши запросы к API с нуля.

| Скрипт | Что делает | Токен |
|--------|-----------|-------|
| `fetch_analytics.py` | Ежедневная статистика канала за 28 дней | `token.json` |
| `fetch_video_report.py` | Статистика по каждому видео: просмотры, удержание, ср. время, подписчики, лайки, комменты, репосты | `token_video.json` |
| `fetch_demographics.py` | Демография: пол, возраст, страны | `token.json` |
| `fetch_traffic_sources.py` | Источники трафика по каналу и по каждому видео (Browse, Suggested, Search и т.д.) | `token_video.json` |

Выгрузки сохраняются в `data/` (папка в .gitignore). Скрипты запускает Наталья на своём Windows-компе с авторизованными OAuth-токенами.

## 2. YouTube Analytics API (нужен OAuth владельца канала)

Метрики (проверяй актуальные названия в документации Google):
- Охват и вовлечение: `views`, `estimatedMinutesWatched`, `averageViewDuration`, `averageViewPercentage`, `likes`, `comments`, `shares`
- Рост: `subscribersGained`, `subscribersLost`
- Удержание: `audienceWatchRatio`, `relativeRetentionPerformance` в разрезе `elapsedVideoTimeRatio` (только по одному видео)
- Аудитория: `viewerPercentage` в разрезах `ageGroup`, `gender`

Разрезы (dimensions):
- `day`: динамика по дням
- `video`: сравнение роликов
- `insightTrafficSourceType`: Browse, Suggested, Search, внешние и т.д.
- `insightTrafficSourceDetail`: детали источника. Для рекомендованного трафика это ID видео, откуда пришёл зритель (используй для проверки кластера)
- `ageGroup`, `gender`, `country`, `deviceType`
- `subscribedStatus`: подписчики против не подписанных

## 3. Показы и CTR обложки

### 3.1. Reporting API

- Показы и CTR **в Analytics API отсутствуют**. Они есть в Reporting API, в отчёте `channel_reach_basic_a1` (метрики `video_thumbnail_impressions` и `video_thumbnail_impressions_ctr`; точные имена сверь с документацией).
- Отчёты создаются через «reporting job»: задачу нужно завести один раз, дальше отчёты формируются ежедневно, данные появляются с задержкой. Историю Google отдаёт ограниченно, поэтому **заведи job как можно раньше** и сохраняй результаты в собственное хранилище.
- Если MCP-сервер обещает CTR через Analytics API, это признак ошибки. Не доверяй таким цифрам.

### 3.2. Ручной экспорт из YouTube Studio (текущий метод)

На практике этот канал получает данные о показах и CTR через **ручной экспорт из YouTube Studio**:
- Studio → Аналитика → конкретное видео → Охват → три точки → Экспорт → ZIP.
- В ZIP два файла: «Данные из таблицы.csv» (по дням) и «Итоговые данные.csv» (суммарно).
- Экспортирует Наталья, передаёт файлы для анализа.

Этот метод работает и даёт проверенные данные. Reporting API — альтернатива для автоматизации, но пока не настроен.

## 4. YouTube Data API v3

- Метаданные: название, описание, теги, длительность, дата публикации, обложки.
- Комментарии (как источник запросов на темы и сигналов об удержании).
- Публичная статистика конкурентов: просмотры, лайки, дата публикации.
- Квота 10 000 единиц в сутки. `search.list` стоит дорого (100 единиц), поэтому по возможности используй `videos.list` и `playlistItems.list` (по 1 единице).

## 5. Собственное хранилище (обязательно)

Завести таблицу снимков (SQLite или Google Sheets): `video_id`, `дата`, `возраст_видео_дней`, показы, CTR, просмотры, средний % просмотра, доли источников трафика. Зачем: сравнение видео в одном возрасте и накопление истории, которой у API может не быть.

Частично это уже делают скрипты из раздела 1 (выгрузки в `data/`).

## 6. Внешние источники

- Google Trends и подсказки поиска (спрос на темы).
- Публичные видео каналов-конкурентов (какие темы и названия получили много просмотров).
- Транскрипты и тепловые карты пересмотров публичных видео (для анализа структуры чужих удачных роликов).

## 7. Ограничения

- Мало видео и мало данных: не делай сильных выводов, помечай уровень уверенности.
- У новых видео метрики за первые 48 часов ещё дозревают, не паникуй по первому дню.
- Демография (возраст/пол) отдаётся в процентах и с порогами приватности: на малых объёмах данных может отсутствовать.
- CTR и показы через Reporting API могут не совпадать с данными Studio на 1–3% — это нормальная погрешность.
